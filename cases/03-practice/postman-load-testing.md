# Кейс 7. Нагрузочное тестирование API через Postman

## Проблема

Нужно было проверить, как API выдерживает **массовую отправку документов** — нагрузочный сценарий на тысячи операций. Выделенного инструмента нагрузочного тестирования под эту задачу не было, а поднимать полноценный фреймворк — долго и избыточно.

Дополнительно всплыла проблема на уровне данных:

> Для нагрузочного прогона требовалось **7000 уникальных `external_id`**. При повторном запуске одних и тех же запросов прогон падал на ошибках валидации: уникальность и обязательность полей.

## Действия

1. Использовал **Postman** — знакомый команде инструмент для API-тестов — как нагрузочный раннер (Run Collection).
2. Собрал отдельную **коллекцию** с запросами, необходимыми для теста, и настроил их так, чтобы повторные запуски не падали.
3. Решил проблему уникальности: вынес поле в переменную окружения `external_id: {{external_id}}` и написал pre-request Script, который генерирует уникальное значение на каждую итерацию.
4. Настроил **Run Collection**: количество итераций, интервал между итерациями, остановку теста при ошибках.
5. Во вкладке **Performance** задал количество параллельных виртуальных пользователей и профиль нагрузки.
6. По итогам прогона экспортировал результаты и оценил скорость выполнения каждого запроса.
7. Оформил инструкцию для коллег — чтобы команда могла повторять нагрузочные прогоны самостоятельно.

## Решение по уникальным ID

Скрипт генерирует на каждый документ уникальный четырёхзначный идентификатор, хранит список использованных чисел и подставляет новое значение в переменную окружения:

```javascript
// Получаем список использованных чисел из переменной окружения
var usedNumbers = pm.environment.get("used_numbers") || [];

// Генерируем уникальное четырёхзначное число
var newNumber;
do {
    newNumber = Math.floor(Math.random() * 9000) + 1000;
} while (usedNumbers.includes(newNumber));

// Добавляем сгенерированное число в список использованных чисел
usedNumbers.push(newNumber);

// Возвращаем список в переменную окружения
pm.environment.set("used_numbers", usedNumbers);

// Подставляем число в external_id
pm.environment.set("external_id", newNumber);
```

Значение берётся в body документа из переменной окружения — каждый запрос уходит с уникальным `external_id`.

## Как настраивался прогон

Прогон настраивался через штатные средства Postman:

1. У коллекции → три точки → **Run collection**.
2. Параметры: количество итераций, интервал между итерациями, остановка при ошибках.
3. Вкладка **Performance**: количество параллельных виртуальных пользователей и профиль нагрузки (как меняется число vUsers в течение теста).
4. Кнопка **Run {Название коллекции}** — запуск.
5. По итогам — экспорт результатов в **JSON** со скоростью выполнения каждого запроса.

> Скриншоты интерфейса не публикуются: содержат данные внутренних тестовых стендов.

- Экспортирована статистика по скорости каждого запроса.
- Подготовлена **инструкция для коллег**: команда повторяет нагрузочные прогоны в Postman самостоятельно, без привлечения автора.
