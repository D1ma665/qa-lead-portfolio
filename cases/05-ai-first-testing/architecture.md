# Архитектура: AI-first Testing Engine

> Как устроен движок: универсальное ядро + конфигурация под каждый сайт.

---

## 🎯 Принцип

> **Ядро (`core/`) — универсальное. Всё под конкретный сайт — в YAML-профиле.**

Один движок обслуживает **разные** сайты заказчиков: поведение меняется
конфигом, а не кодом.

## 🧩 Компоненты

| Компонент | Ответственность | Универсально? |
|---|---|---|
| **Profile** | YAML-настройки сайта: URL, домены, локаль, адаптер, safety | ❌ под проект |
| **Adapter** | Поведение под тип сайта: `classic` / `spa` | ✅ ядро |
| **Crawler** | Собирает интерактивные элементы страницы | ✅ ядро |
| **Brain** | LLM решает: что нажать; судит, баг ли это | ✅ ядро |
| **Executor** | Выполняет клики через Playwright | ✅ ядро |
| **Oracle** | Детектит сигналы багов: HTTP 500, JS-errors, blank page | ✅ ядро |
| **Reporter** | Сохраняет находки: JSON + Markdown + скриншоты | ✅ ядро |
| **Recorder** | Превращает баг в pytest-тест (регресс) | ✅ ядро |
| **Engine** | Оркестратор: очередь страниц, лимиты, запуск | ✅ ядро |

## 📄 Профиль (пример)

```yaml
name: client-ivanov
start_url: https://staging.ivanov.ru
allowed_domains:
  - ivanov.ru
locale: ru
adapter: classic            # classic | spa
readonly: false

safety:
  forbidden_keywords: [удалить, оплатить, деактивировать]
  forbidden_url_patterns: [logout, /delete, /checkout]

limits:
  max_pages: 30
  max_depth: 3
  max_actions_per_page: 15
```

## 🔁 Жизненный цикл обхода

1. **Загрузка профиля** — валидация YAML, домены, лимиты.
2. **Адаптер** — выбор стратегии ожидания/навигации (`classic` vs `spa`).
3. **Crawl** — сбор элементов текущей страницы.
4. **Decision** — Brain выбирает следующее действие.
5. **Safety-check** — действие не в чёрном списке? домен разрешён?
6. **Execute** — Playwright выполняет клик/ввод.
7. **Observe** — Oracle ловит сигналы; Reporter пишет находку.
8. **Enqueue** — новые ссылки в очередь; лимиты соблюдены.
9. **Record** — Recorder генерирует регресс-тесты.

---

## 🧠 Роль LLM (Brain)

- **Выбор действия** — что нажать дальше, с учётом контекста.
- **Суждение о баге** — «ожидаемое поведение» или дефект.
- **LLM-as-a-Judge** — оценка результата шага.

> ⚠️ LLM может ошибаться → **человек ревьюит** каждую находку.
> Ложное срабатывание = сигнал доработать профиль или промпт.

---

## 🛡 Безопасность

| Слой | Защита |
|---|---|
| Домены | `allowed_domains` — не выходить за пределы |
| Действия | `forbidden_keywords`, `forbidden_url_patterns` |
| Режим | `readonly: true` на проде |
| Лимиты | `max_pages`, `max_depth`, `max_actions_per_page` |
| Секреты | `.env` в `.gitignore` |

---

## ➕ Расширение

| Что добавить | Как |
|---|---|
| Новый тип сайта | Новый адаптер (ядро, без правки под проект) |
| Новый детектор багов | Правило в Oracle |
| Новый формат отчёта | Экспортёр в Reporter |
| Другая модель LLM | Замена провайдера в Brain |

## 🎯 Итог

Архитектура даёт **масштабируемость**: один движок — много сайтов,
конфиг вместо кода, безопасность по умолчанию, человек — на ревью
и развитии системы.
