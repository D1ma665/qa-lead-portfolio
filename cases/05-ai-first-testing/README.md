# 🧠 AI-first Testing — AI-агент для тестирования веб-приложений

> Кейс из портфолио QA Lead.
> Проект: движок, который обходит сайт заказчика, находит баги
> и автоматически генерирует регресс-тесты.

## 🎯 Задача

Классический QA тормозит релизы: ручной клик по кнопкам,
ручное написание автотестов, долгая реакция на регресс.
Нужно было **встроить ИИ в процесс с самого начала** —
подход **AI-first**, а не «ИИ как игрушка сбоку».

---

## 💡 Решение

AI-агент (Python + Playwright + LLM), который:

1. Собирает все элементы страницы (кнопки, поля).
2. Сам решает, что нажать — AI-мозг оценивает контекст.
3. Ловит сигналы багов (HTTP 500, JS-ошибки, пустая страница).
4. Автоматически генерирует регресс-тесты.

**Смена роли QA:** с «ручного кликера» — на **наставника агента**:
ревью находок, уточнение логики под конкретный сайт.

---

## 🏗 Архитектура

```
Профиль (YAML) ──► Engine (обход)
     │
     ├─► Crawler: собрал элементы
     ├─► Brain: "кликни #7" ──► Executor: кликнул
     ├─► Oracle: "500-я ошибка" ──► Reporter: сохранил баг
     └─► ссылки ──► в очередь обхода

Баг (JSON) ──► Recorder ──► pytest-тест (регресс)
```

**Ключевой принцип:** ядро (`core/`) универсально,
всё под конкретный сайт — в YAML-профиле.
Один движок работает на разных сайтах заказчиков.

---

## 🧩 Компоненты

| Компонент | Роль |
|---|---|
| Profile | YAML с настройками одного сайта (заказчика) |
| Adapter | Правила поведения: `classic` или `spa` |
| Crawler | Собирает все кнопки/поля на странице |
| Brain | AI-мозг: решает, что кликнуть; судит, баг ли это |
| Executor | Реально выполняет клики через Playwright |
| Oracle | Ловит сигналы багов (ошибки 500, JS-ошибки, пустая страница) |
| Reporter | Сохраняет баги в JSON + Markdown + скриншоты |
| Recorder | Превращает найденный баг в автотест |
| Engine | Оркестратор: гоняет обход по страницам |

## 🛡 Безопасность

- 🔴 Только тестовые стенды; прод — исключительно `readonly: true`.
- 🔴 `forbidden_keywords` (удалить / оплатить / деактивировать).
- 🔴 `forbidden_url_patterns` (logout, /delete, /checkout).
- 🔴 `allowed_domains` — агент не должен уйти на чужой сайт.
- 🟡 Лимиты `max_pages`, `max_depth` — защита от бесконечного обхода
  и роста счетов за токены.
- 🟢 Сомневаешься — спроси наставника до запуска.

---

## 🔁 Процесс (как это работает на практике)

1. **Профиль** — копия `example.yaml` под заказчика (`name`, `start_url`, `allowed_domains`).
2. **Тип сайта** — `classic` (текст сразу в HTML) или `spa` (контент в `<div id="root">`).
3. **Safety** — чёрный список опасных действий.
4. **Обход** — `python main.py --profile profiles/<client>.yaml`.
5. **Ревью** — QA проверяет каждый баг руками, правит severity.
6. **Регресс** — `python run_regression.py --profile ... --regen`.

## 📈 Результат

- QA-команда переходит на **AI-first**: рутина — агенту, людям — ревью и развитие движка.
- Готовый онбординг: новичок за **3 дня** доходит до самостоятельного запуска.
- Ложные срабатывания не проблема, а **сигнал доработать** профиль/промпт.
- Кейс демонстрирует умение **строить** AI-first QA, а не только пользоваться ИИ.
