## 🎯 Управление и команда

### [Кейс 1. Система метрик качества, привязанная к бизнес-целям](cases/01-management/metrics-system.md)

Двадцать метрик вместо разрозненных отчётов: каждая привязана к бизнес-цели и имеет формулу, целевой показатель и условия применения.

**Ключевые результаты:**

- Доля дефектов, найденных после релиза: **18% → 7%**
- Критические дефекты в проде: **9% → 2%**
- Время реакции на дефект: **4 часа → 20 минут**
- Cycle Time: **4.5 → 2.5 дня**

**📚 Артефакт:** [qa-metrics.csv](artifacts/qa-metrics.csv) — 20 метрик с формулами и целями

### [Кейс 2. Матрица компетенций 60+ и система грейдирования](cases/01-management/competency-matrix.md)

Матрица из 60+ компетенций в 6 продуктовых группах, приоритеты, 5-балльная шкала, 12 обезличенных сотрудников. На её основе — прозрачное грейдирование и расчёт премий.

**Ключевые результаты:**

- Прозрачные критерии роста вместо субъективных оценок
- Единая шкала для 12 человек и 6 продуктовых направлений
- Автоматический расчёт грейда и премии

**➡️ Интерактивная реализация:** [приложение «Калькулятор грейдов и премий QA»](#-интерактивный-калькулятор-грейдов-и-премий-qa)

## ⚙️ Процессы и релизы

### [Кейс 3. Unit-экономика QA-команды](cases/01-management/unit-economics.md)

Модель, которая показывает стоимость закрытой задачи и связывает бюджет QA с результатом. Абсолютные суммы заменены на относительные индексы для сохранения конфиденциальности.

**Ключевые результаты:**

- Стоимость закрытой задачи: **индекс 81** по факту против **100** по плану
- Рост эффективности бюджета без роста численности
- Прозрачный ответ на вопрос «за что мы платим»

**📚 Артефакт:** [unit-economics.csv](artifacts/unit-economics.csv) — расчёт через относительные индексы (план/факт)

### [Кейс 4. Автоматизация QA-рутины и внутренние инструменты](cases/02-processes/qa-automation.md)

n8n-воркфлоу закрывают повторяющиеся задачи: сбор метрик, уведомления о дефектах, отчёты по релизам. Рутина переведена в автоматический режим.

**Ключевые результаты:**

- Ручные операции по сбору статусов — сокращены до нажатия кнопки
- Единая точка правды по качеству релиза
- Освободившееся время — на исследовательское тестирование

**📚 Артефакты:** [qa-dod.md](artifacts/qa-dod.md) · [bug-reports-sample.md](artifacts/bug-reports-sample.md) · [checklist-auth-mobile.md](artifacts/checklist-auth-mobile.md)

### [Кейс 5. Регламент управления релизами](cases/02-processes/release-management.md)

Регламент, который определяет критерии готовности релиза, роли, точки принятия решения и порядок отката. Согласован между QA, разработкой, продуктом и эксплуатацией.

**Ключевые результаты:**

- Единые критерии Go/No-Go для всех релизов
- Снижение количества «горячих» фиксов после релиза
- Прозрачная ответственность между подразделениями

## 🚀 Интерактивный калькулятор грейдов и премий QA

Живая демонстрация методологии из [Кейса 2](#-управление-и-команда): не статичная таблица, а рабочее веб-приложение, которое считает грейд, оценку выполнения целей и премию в реальном времени.

> 🚀 **Live demo:** [qa-grading-app.onrender.com](https://qa-grading-app.onrender.com) — первый заход \~30–50 сек (бесплатный тариф).

> Приложение — самостоятельный проект в папке [`app/`](app/). Поднимается локально одной командой, без компиляторов и внешних сервисов.

**Что внутри:**

- Сотрудники и их оценки по компетенциям
- Бизнес-цели Ц1–Ц3 и шаблоны целей по грейдам
- Расчёт грейда из компетенций и покрытия
- Дашборд: покрытие, приоритеты, владельцы, bus factor
- История оценок по периодам (например, 2026-Q4)
- Экспорт в Excel

## 🛠 Стек

**Процессы:** Scrum, Kanban, QA DoD, тест-стратегия, метрики качества (Escape Rate, Cycle Time, покрытие, crash-free rate), unit-экономика QA

**Тестирование:** функциональное, регрессионное, интеграционное, мобильное, нагрузочное, исследовательское, тестирование LLM-сервисов

**Автоматизация и инструменты:** Python, pytest, Postman, JMeter, n8n, Git, SQL

**AI/LLM:** оценка качества ответов, работа с недетерминированностью, RAG, prompt injection, регрессионные наборы для LLM

## 📌 О приватности

Все артефакты в этом репозитории обезличены:

- сотрудники обозначены индексами QA-1…QA-12 вместо имён;
- финансовые показатели переведены в относительные индексы (база 100);
- названия клиентов, банков и работодателей не раскрываются;
- персональные данные, контакты третьих лиц и внутренние документы отсутствуют.

Цифры и кейсы отражают реальный опыт, но приведены к обезличенному виду для публикации.
