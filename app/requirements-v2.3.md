✅ Все три бизнес-цели зафиксированы. `U3` совпадает с уже реализованным расчётом bus factor (раздел 7).

## 2.4 Ключевые цели и их метрики

✅ **Целей ровно три**, каждая привязана к своей бизнес-цели. Тип метрики различается — это осознанно.

| Цель | Бизнес-цель | Метрики | Тип |
|---|---|---|---|
| **Ц1** | U1 Качество продукта | **escape rate** (доля дефектов, ушедших в прод), стабильность релиза | качественная |
| **Ц2** | U2 Снижение Time to market | время прогона регресса, время от готовности до релиза | количественная |
| **Ц3** | U3 Снижение зависимости от людей | bus factor проектов с участием, число обученных людей, покрытие критичных компетенций | качественная |

⚠️ **Число найденных дефектов не является метрикой эффективности.** Плохие тесты дают больше находок. Количественные метрики используются только в паре с качественными.

### Правила метрик

| Правило | Смысл |
|---|---|
| Метрика **относительная**, не абсолютная | «утекло 0 из 12», а не «нашёл 50 багов» |
| Значение **до/после** согласуется заранее | исключает подгонку после факта |
| Для Ц3 приоритет — bus factor | метрика уже реализована в приложении |

## 4.3 Взвешенное среднее по трём целям

```
выполнение_цели = kpi_fact / kpi_plan * 100
взвешенный_процент = Σ(выполнение_цели × weight)
```

✅ Вес по умолчанию — **1/3 на каждую из трёх** (сумма = 1.0).
Пример: Ц1 = 120%, Ц2 = 90%, Ц3 = 75% → `95%` → **C**.

✅ **«КПИ выполнены» = взвешенное среднее ≥ 100%.**
✅ Ц3 участвует в расчёте **наравне** с Ц1 и Ц2 — иначе оценка сводится к «нашёл баг / успел к сроку» и поощряет имитацию активности.
⚠️ Для периодов, где Ц3 ещё не ставилась, веса Ц1/Ц2 = 50/50.
