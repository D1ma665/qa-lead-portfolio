## 2. Модель данных

### 2.1 Сотрудники

```json
{
  "name": "Иванов М.И.",
  "scores": { "Название компетенции": 3 }
}
```

✅ Оценки хранятся **по имени компетенции**, а не по индексу — это позволяет менять справочник без сдвига оценок.

### 2.2 Проекты

```json
{ "name": "Проект С", "owners": { "Кузнецов Д.А.": 3, "Лебедев Р.Т.": 2 } }
```

| Поле | Смысл |
|---|---|
| `name` | название проекта |
| `owners` | ФИО владельца → балл владения (0–4) |

✅ Владелец **всегда** имеет балл. «Кто может подменить» отдельным списком **не вводится** — это расчётная величина по баллам владельцев.

## 3. Компетенции — единый источник

### 3.1 Решение ✅

| Слой | Роль |
|---|---|
| `state["competencies"]` | **единственный рабочий список**, редактируется через UI |
| `config.COMPS` | **seed** — стартовый набор, используется только если `state` пуст |

✅ Добавление, редактирование и удаление компетенций — **только** через страницу `/comps`. Правка `config.py` руками на работающее приложение не влияет.

### 3.2 Формат записи

```python
("Название", "Категория", приоритет, "Цель")
# пример: ("Качество тестирования", "Проф навыки", 1, "Ц1")
```

| Поле | Допустимые значения |
|---|---|
| Категория | `Проф навыки`, `Инструменты`, `Soft skills` |
| Приоритет | `1` … `3` (п1 / п2 / п3) |
| Цель | `Ц1` … `Ц4` |

### 3.3 Маршруты ✅

| Маршрут | Действие |
|---|---|
| `GET /comps` | список компетенций |
| `/comps/add` | добавить |
| `/comps/edit` | редактировать |
| `/comps/del` | удалить |

✅ Проверено вручную: добавление → видно в `/matrix` → удаление → после перезапуска сохраняется.

### 3.4 Ограничения

⚠️ Проверки на похожие названия нет — при опечатке создаётся дубль.
⚠️ При полной очистке `state.json` список восстановится из `config.COMPS`.

## 4. Bus factor проектов

### 4.1 Константы

```python
COVERAGE_MIN = 3        # минимальное покрытие компетенции
BUS_FACTOR_RISK = 2     # порог «сильного» владельца
```

✅ Порог **не зашивается в код**, а берётся из `config` (`state.py`, функция расчёта bus factor).

### 4.2 Расчёт

```python
able = [name for name, score in owners.items() if score >= config.BUS_FACTOR_RISK]
```

| Кол-во сильных | Статус | Подпись бейджа |
|---|---|---|
| 1 | `риск` | `мало людей` |
| 2 | `тесно` | `тесно` |
| ≥ 3 | `ок` | `ок` |

### 4.3 Колонки таблицы `/projects` ✅

| Колонка | Содержимое |
|---|---|
| Владельцы (балл) | `Кузнецов Д.А. (3), Лебедев Р.Т. (2)` |
| **Сильных владельцев (≥2)** | число владельцев с баллом ≥ `BUS_FACTOR_RISK` |
| Статус | бейдж по таблице 4.2 |

✅ Формулировка «Могут подменить» **убрана** — она вводила в заблуждение: показывала силу владельцев, а не замену.
✅ Таблица растянута на всю ширину страницы.

### 4.4 Пример ✅

| Проект | Владельцы | Сильных (≥2) | Статус |
|---|---|---|---|
| Проект С | Кузнецов Д.А. (3), Лебедев Р.Т. (2) | 2 | `тесно` |
| Проект N | Новиков М.И. (3), Морозов Д.В. (1) | 1 | `мало людей` |
| Проект F | Волков С.Н. (4) | 1 | `мало людей` |

⚠️ Открытый вопрос: порог `BUS_FACTOR_RISK = 2` пропускает владельца с баллом 2. Если считать это слабым — значение меняется на `3`, подпись станет «Сильных владельцев (≥3)».
