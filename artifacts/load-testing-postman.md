# Нагрузочное тестирование API в Postman

Postman известен в первую очередь как инструмент функционального тестирования API, но его можно применять и для **нагрузочного тестирования**. Ниже — подход, который использовался на практике, и инструкция для команды.

## Преимущества

| Преимущество | Описание |
|---|---|
| **Простота в использовании** | Интуитивный интерфейс: создание и отправка запросов доступны даже новичкам |
| **Лёгкая настройка окружения** | Environments позволяют менять конфигурацию под разные сценарии нагрузки |
| **Интеграция с мониторингом и отчётностью** | Интеграция с сервисами мониторинга, генерация детальных отчётов о производительности |
| **Создание сценариев** | Последовательности запросов и условные операторы моделируют реальные сценарии использования |

## Подготовка первого нагрузочного теста

1. Создать отдельную **коллекцию** с запросами для теста.
2. Настроить запросы так, чтобы при повторных запусках они не падали: уникальность полей, обязательность полей.

### Проблема: уникальные идентификаторы

При первом нагрузочном тесте возникла задача: **7000 уникальных `id`** для отправки документов.

> Если в коллекции 2 запроса, то при запуске 7000 итераций выполнится **14000 запросов**.

### Решение: генерация уникального ID через pre-request Script

В поле задаётся переменная окружения `external_id: {{external_id}}`, во вкладке **Scripts** прописывается алгоритм:

```javascript
// Получаем список использованных чисел из переменной окружения
var usedNumbers = pm.environment.get("used_numbers") || [];

// Генерируем уникальное четырёхзначное число
var newNumber;
do {
    newNumber = Math.floor(Math.random() * 9000) + 1000;
} while (usedNumbers.includes(newNumber));

// Добавляем сгенерированное число в список использованных чисел
usedNumbers.push(newNumber);

// Устанавливаем список использованных чисел обратно в переменную окружения
pm.environment.set("used_numbers", usedNumbers);

// Устанавливаем сгенерированное число в переменную окружения external_id
pm.environment.set("external_id", newNumber);
```

Скрипт генерирует на каждый документ **уникальный идентификатор** и подставляет его в переменную окружения, откуда значение берётся в body документа.

## Запуск теста

1. У коллекции нажать три точки → **Run collection**.
2. Задать параметры: количество итераций, интервал между итерациями, остановку при ошибках.
3. Во вкладке **Performance** — количество параллельных виртуальных пользователей и профиль нагрузки (как меняется число vUsers в течение теста).
4. Нажать **Run {Название коллекции}**.

## Результаты

- Поочерёдное выполнение запросов с заданными параметрами.
- Напротив каждого запроса — ответ сервера с кодом и результаты тестов.
- Возможность **паузы** и **остановки** в любой момент.
- **Экспорт результатов в JSON** — с указанием скорости выполнения каждого запроса.
