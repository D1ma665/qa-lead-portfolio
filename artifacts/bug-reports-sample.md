## Как оформляю баг-репорты

Каждый дефект состоит из обязательных блоков:

- **Окружение** — устройство, версия ОС, версия приложения.
- **Шаги воспроизведения** — точная последовательность действий, приводящая к дефекту.
- **Ожидаемый результат** — что должно быть по требованиям/логике.
- **Фактический результат** — что происходит на самом деле.
- **Статус** — OK / NOK, плюс оценка серьёзности.

Такой формат позволяет разработчику воспроизвести дефект без уточняющих вопросов, а аналитику и продукту — быстро оценить влияние на пользователя.

## Bug_1. Регистрация на несуществующий email проходит без предупреждения

**Окружение:** iPhone 5, iOS 12.4.7, приложение v 2.0.8.5
**Серьёзность:** High
**Статус:** NOK

**Шаги воспроизведения:**
1. Открыть приложение.
2. Нажать «Create account».
3. Ввести несуществующий email-адрес в поле «Email».
4. Ввести пароль в поле «Password» (например, `As1234567`).
5. Нажать «Create my Free Account».

**Ожидаемый результат:** появляется уведомление о невозможности регистрации на указанный адрес, аккаунт не создаётся.

**Фактический результат:** сообщение об ошибке отсутствует, аккаунт регистрируется.

**Комментарий QA:** необходимо уточнить требования по подтверждению email. Если регистрация на новый адрес допустима — дефект переквалифицировать в «отсутствие валидации формата» и уточнить ожидаемое поведение.

## Bug_2. Неверное сообщение об ошибке при вводе невалидного пароля

**Окружение:** iPhone 5, iOS 12.4.7, приложение v 2.0.8.5
**Серьёзность:** Medium
**Статус:** NOK

**Шаги воспроизведения:**
1. Открыть приложение.
2. Нажать «Log in».
3. Ввести email зарегистрированного пользователя в поле «Email».
4. Ввести неверный пароль в поле «Password» (например, `12`).
5. Нажать «Log in».

**Ожидаемый результат:** появляется уведомление «Please enter valid password».

**Фактический результат:** появляется уведомление «Account not found».

**Влияние:** пользователь вводит в заблуждение — система сообщает о ненайденном аккаунте, хотя email существует. Ошибка затрудняет диагностику проблемы самим пользователем.

## Bug_3. Возможна отправка пустого отчёта

**Окружение:** iPhone 5, iOS 12.4.7, приложение v 2.0.8.5
**Серьёзность:** Medium
**Статус:** NOK

**Шаги воспроизведения:**
1. Открыть приложение.
2. Перейти в раздел «Settings».
3. Перейти в раздел «Report a problem».
4. Ввести два пробела в поле «Contact information».
5. Ввести два пробела в поле «Describe the problem».
6. Нажать «Send».

**Ожидаемый результат:** заявка не отправляется, номер заявки не присваивается.

**Фактический результат:** заявка отправляется, номер заявки присваивается.

**Влияние:** поддержка получает пустые обращения, растёт время обработки и нагрузка на первую линию.

## Bug_4. Доступен developer mode

**Окружение:** iPhone 5, iOS 12.4.7, приложение v 2.0.8.5
**Серьёзность:** High (безопасность)
**Статус:** NOK

**Шаги воспроизведения:**
1. Открыть приложение.
2. Перейти в раздел «Settings».
3. Дважды нажать на «version 2.0.8.5».

**Ожидаемый результат:** скрытый developer mode недоступен в релизной сборке.

**Фактический результат:** developer mode становится доступным.

**Влияние:** в релизной сборке пользователю доступны отладочные функции — потенциальный риск безопасности и нестабильного поведения приложения.

## Bug_5. Поля «Email» и «Password» не фильтруют emoji и запрещённые символы

**Окружение:** iPhone 5, iOS 12.4.7, приложение v 2.0.8.5
**Серьёзность:** Medium
**Статус:** NOK

**Шаги воспроизведения:**
1. Открыть приложение.
2. Перейти на страницу авторизации.
3. Установить курсор в поле «Email».
4. Переключить раскладку клавиатуры на emoji.
5. Ввести emoji в поле «Email».

**Дополнительно:** поля «Email» и «Password» не фильтруют ввод при вставке — emoji можно вставить через буфер обмена.

**Ожидаемый результат:** поля принимают только допустимые символы; ввод emoji и других запрещённых символов блокируется или отображается ошибка валидации.

**Фактический результат:** emoji принимаются полями без фильтрации.

**Влияние:** некорректные данные попадают в систему, возможны ошибки при дальнейшей обработке (хранение, сопоставление, восстановление доступа).
